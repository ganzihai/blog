# 01 / 认知刷新：从“网盘搬运工”到“家庭影院自治”

先看一张绝大多数影视发烧友每天都在重复的低效链路：

```
[刷到心仪影片] ➔ [记在备忘录/豆瓣] ➔ [天天去网盘搜资源] ➔ [转存到网盘暂存区]
       ➔ [手动重命名清洗广告] ➔ [手动触发 SmartStrm 扫描] ➔ [播放发现字幕不对重新找]
```

这套传统玩法之所以越用越累，核心原因在于存在四大致命断层：

**1\. 意图与执行割裂**：你在手机豆瓣点了个想看，但你的 NAS 根本不知道；

**2\. 版权窗口期盲区**：院线电影下映到流媒体首播（4K WEB-DL 释出）通常有 1\~3 个月窗口期，人工盯盘既费时又容易错过；

**3\. 字幕早产与机翻陷阱**：官方流媒体上线的当天（Day 0），流出的版本大多是简陋官方字幕甚至纯生肉，冲动观看往往被极差的机翻毁了整部好片；

**4\. 云端暂存区积压**：网盘转存默认堆在 `/最近接收`，而 SmartStrm 只监听标准分类目录。没有自动化归整，海报墙始终不会出现新片。

真正的现代极客影音系统，绝不是让人去伺候机器，而是让机器在幕后默默值守：**你在生活里只管随手标记心动大片，剩下的全链路全交给自动化大脑完成。**

### 玩法一：待播院线片与大片出种雷达（Watchmode 版权库）

**痛点场景**：刚在电影院看完预告片，或者某部好莱坞大片刚在北美下映，每天都在群里问“流媒体出种了吗？”

**运作逻辑**：脚本通过 Watchmode 全球版权接口，每日自动巡检该片在全球各大流媒体平台（Netflix、Apple TV+、Prime Video、Max、Disney+）的发行计划。只要检测到 `source_type == "sub"`（订阅制流媒体首发）且首播日期确定，出种雷达立即捕获并记入待抓取池。

**底层核心实现**：

```
import urllib.request, json

def check_streaming_release(title_id, api_key):
    """检查影片在全球主流平台的流媒体上映日历"""
    url = f"https://api.watchmode.com/v1/title/{title_id}/sources/?apiKey={api_key}®ions=US,HK,TW"
    req = urllib.request.Request(url, headers={"User-Agent": "Mozilla/5.0"})
    with urllib.request.urlopen(req, timeout=10) as resp:
        sources = json.loads(resp.read().decode())

    # 筛选正式订阅流媒体上线源 (排除点播租借)
    sub_sources = [s for s in sources if s.get("type") == "sub"]
    return sub_sources
```

### 玩法四：豆瓣 App 想看动态全自动同步（零门槛无感交互）

**痛点场景**：在手机上刷豆瓣看到一部冷门佳作，还要复制片名去网盘 App 一个个搜索转存，极为繁琐。

**运作逻辑**：利用豆瓣公开的 XML 订阅流（`feed/people/{uid}/interests`）。系统静默拉取订阅流，一旦发现你点击了【想看】，立刻提取标准片名，调用 TMDb 补全海报与演职员，并自动触发 FNOS 盘搜。网盘已有资源的秒级转存入库；未上映的自动挂载至出种雷达。

**底层极简探测代码**：

```
import urllib.request, xml.etree.ElementTree as ET

def fetch_douban_wishlist(uid):
    """通过公开 XML 订阅源提取新增想看条目"""
    feed_url = f"https://www.douban.com/feed/people/{uid}/interests"
    req = urllib.request.Request(feed_url, headers={"User-Agent": "Mozilla/5.0"})
    with urllib.request.urlopen(req, timeout=10) as r:
        root = ET.fromstring(r.read().decode("utf-8", errors="ignore"))

    items = root.find("channel").findall("item")
    wishlist = []
    for it in items:
        title = it.find("title").text.strip()
        link = it.find("link").text.strip()
        if title.startswith("想看") and "movie.douban.com" in link:
            clean_name = title[2:].strip()
            wishlist.append({"title": clean_name, "link": link})
    return wishlist
```

def check_subhd_mature(title):

    q = urllib.parse.quote(title.strip())

        "X-Requested-With": "XMLHttpRequest",
        "Referer": "https://subhd.tv/"

    d_req = urllib.request.Request(detail_url, headers={"User-Agent": "Mozilla/5.0"})
    with urllib.request.urlopen(d_req, timeout=10) as dr:
        html = dr.read().decode("utf-8", errors="ignore")

# 04 / 避坑排雷：前线生产环境五大铁律

这套流水线跑通并不复杂，但要保证它常年在后台静默值守而不崩塌，必须严格恪守以下前线避坑规约：

**1\. 多网盘源死链顶替陷阱**：在飞牛影视中，如果夸克和 115 存在同名片源，而夸克端正片失效却残留了孤儿 `.strm`，飞牛会优先尝试播放失效源并无限报错 500。解法是：执行 SmartStrm 镜像同步时必须严格追加 `--delete` 参数，彻底清理本地孤儿直链。

**2\. 网盘目录绝对扁平化原则**：很多朋友喜欢把合集建三四层子目录，SmartStrm 和刮削器最多向上探查两级，过深会导致飞牛完全不识别。所有正片必须标准化提升为 `/影音/电影/电影中文名 (年份)/`。

**3\. 飞牛图片中转两级散列硬编码限制**：飞牛内置的图片反代服务强制要求路径符合 `/img/{2位}/{2位}/poster.webp`。如果手动注入海报时直接写单级目录，Nginx 会直接返回 501 导致前端海报全裂开白板。

**4\. 目录与命名规范化隔离**：公网网盘端（115/夸克）统一采用中性英文或拼音命名（如 `Blind.Shaft.2003`），避免中文标点与特殊符号导致跨系统同步报错；中文海报与剧情简介留给本地飞牛解耦呈现，保持云端目录干净规范。

**5\. 上游 API 强缓存与防限流设计**：Watchmode 等服务有严格的月度调用配额。我们在底层构建了 SQLite 强缓存（影片详情缓存 14 天、播放源缓存 2 天），使得日常定时巡检的缓存命中率达到 95% 以上，既保护了免费配额，又杜绝了 429 请求频次超限。

# 05 / 适合谁与不适合谁：方案适用边界

在把这套自动化全盘托出前，必须负责任地讲清它的适用边界：

**强烈推荐的人群**：

拥有飞牛私有云（fnOS）并重度使用 115 网盘或夸克网盘的用户；

反感昂贵机械硬盘阵列噪音与成本，追求免下载、大容量云端 STRM 极速直链串流的极客；

经常在手机豆瓣随手标记电影，期望“随手一记、回家直接开大屏”的观影发烧友。

**不建议折腾的人群**：

家庭宽带上行极低（低于 30Mbps）、网盘原盘直链播放经常卡顿的网络环境；

追求极致本地冷备、坚持用物理蓝光机或数十块机械硬盘囤积原盘 ISO 的纯松鼠党用户；

观看需求仅限电视直播或短剧，对欧美流媒体、外挂精校字幕毫无需求的用户。
